## 🎯 О проекте

Этот проект представляет собой законченную, отказоустойчивую, событийно-ориентированную микросервисную систему, которая анализирует матчи Dota 2 в реальном времени и предсказывает вероятность смерти персонажа на будущих временных горизонтах (**1, 5, 10, 15 и 20 секунд**). Система визуализирует опасные зоны карты в виде интерактивной **тепловой карты 32×32**, накладываемой на мини-карту Dota 2.

### Основные цели:
1. **Автоматический парсинг реплеев и построение датасета:** Высокопроизводительный конкурентный парсер на Go, обрабатывающий сырые логи матчей в формате JSONL из OpenDota.
2. **Классификация с помощью машинного обучения:** Обучение надежных моделей бинарной классификации (CatBoost против логистической регрессии) для различных временных горизонтов с тщательной борьбой с дисбалансом классов и предотвращением утечки данных.
3. **Обработка GSI в реальном времени:** Обработка игровой телеметрии в реальном времени через интерфейс Game State Integration (GSI) от Valve.
4. **Инференс и WebSocket-стриминг:** Распределенный конвейер инференса через Redis Streams, доставляющий матрицы вероятностей в реальном времени.
5. **Интерактивный фронтенд:** Легковесное SPA-приложение (React 18, TypeScript, Vite) для управления сеансами, конфигурацией и отрисовки тепловой карты в реальном времени.

---

## 🏗 Архитектура и микросервисы

Система построена на основе разделенной микросервисной архитектуры, координируемой через **PostgreSQL** (историческая аналитика и датасет) и **Redis** (состояние сеансов, кэширование и **Redis Streams** для событийно-ориентированного обмена сообщениями).

```
[Dota 2 Client / GSI] 
       │ (HTTP POST /gsi-input)
       ▼
[GSI Processor Service (Python/FastAPI)] 
       │ (Публикация в Redis Stream: inference:input)
       ▼
[ML Inference Service (Python/FastAPI + CatBoost)] 
       │ (Обновление Redis: heat_map:<token>)
       ▼
[Backend Service (Go / Chi / Redis)] 
       │ (WebSocket /ws/predictions)
       ▼
[Frontend Web App (React 18 + Vite + Nginx)]
```

### Основные компоненты:
1. **Парсер и построитель датасета (Go):** Использует паттерн *Worker Pool*, масштабируемый до `runtime.NumCPU()`. Разделяет каждый матч на 3 конкурентные горутины (трекинг состояния героев, видение Radiant, видение Dire) и выгружает чистые векторы признаков в PostgreSQL в рамках одной транзакции.
2. **GSI Processor (`gsi_processor`):** Микросервис на FastAPI, принимающий состояния игры в реальном времени через GSI, проверяющий схемы через Pydantic, контролирующий активные токены сеансов, поддерживающий снимки скользящего окна в Redis и отправляющий записи в Redis Streams.
3. **Inference Service (`inference_service`):** Потребитель Redis Streams, загружающий предобученные артефакты моделей (`CatBoost` / `Logistic Regression`), формирующий пакетные предсказания для позиции героя или по всей сетке 32×32 и записывающий вычисленные тепловые карты в Redis.
4. **Backend Service (`backend`):** Сервис на Go 1.24 с использованием `go-chi`. Управляет REST-эндпоинтами (`/api/start`, `/api/stop`, `/health`) и WebSocket-стримингом (`/ws/predictions`) с 60-минутным TTL сеансов в Redis.
5. **Frontend (`frontend`):** Приложение на React 18 / TypeScript, отрисовывающее тепловые карты в реальном времени с помощью HTML5 `ImageData` на `Canvas`, управляющее состояниями подключения и генерирующее файлы конфигурации VDF.

## 📊 Пайплайн данных и генерация признаков

Датасет содержит **~700 000 снимков состояния матча**, извлеченных из 2 000 матчей. Каждая запись представлена **105 признаками**, разделенными на 7 семантических групп:

1. **Контекст матча и глобальные признаки:** `match_id`, `game_time`, `is_day`, `is_radiant`, `radiant_score`, `dire_score`.
2. **Состояние героя:** `hero_id`, `level`, `kills`, `deaths`, `assists`, `last_hits`, `denies`, `gold`, `net_worth`, `xp`, `health`, `mana`, `max_health`, `max_mana`, атрибуты (`strength`, `agility`, `intellect`), `magical_resistance`, `armor`, `bkb_cooldown`, `movespeed`, пространственные координаты (`x`, `y`, `square`).
3. **Способности:** 16 признаков, отслеживающих уровень, дальность применения, стоимость маны и перезарядку всех 4 основных способностей героя (`ability1_level` и др.).
4. **Окружение и видение:** Расстояние до ближайшей башни союзников/врагов (`nearest_ally_tower_distance`, `nearest_enemy_tower_distance`). Симуляция истинного видения, радиусов дня/ночи, невидимости, дымов (Smoke) и блокировки ландшафтом/деревьями.
5. **Матрица угроз врагов (`enemy_1` — `enemy_5`):** Для каждого из 5 вражеских героев: имя героя, координаты последнего появления (`last_seen_x`, `last_seen_y`), квадрат карты, расстояние и время с момента последнего наблюдения.
6. **Инвентарь / Предметы (бинарные флаги):** `item_black_king_bar`, `item_blink`, `item_force_staff`, `item_basher`, `item_abyssal_blade`, `item_nullifier`, `item_lotus_orb`, `item_travel_boots`, `item_tpscroll`, `item_phase_boots`, `item_silver_edge`, `item_heart`, `item_sphere`, `item_manta`, `item_blade_mail`, `item_aeon_disk`, `item_pipe`.
7. **Целевые переменные (Target):** Бинарные флаги, указывающие на смерть в течение следующих 1, 5, 10, 15 или 20 секунд.

## 🤖 Модели машинного обучения и результаты

Модели бинарной классификации были обучены для 5 различных временных горизонтов (1с, 5с, 10с, 15с, 20с). Разбиение данных выполнялось строго с группировкой по `match_id` для предотвращения утечки данных. Дисбаланс классов решался оптимизацией `class_weight` и контролируемой негативной выборкой (приблизительно 87.5% положительных событий смерти против 12.5% случайных интервалов простоя).


### Основные выводы:
- **CatBoost** стабильно превосходил логистическую регрессию по всем метрикам и временным горизонтам благодаря превосходной обработке нелинейных взаимодействий, категориальных признаков (One-Hot Encoded ID героев) и устойчивости к шумам.
- **Скорость инференса:** Среднее время инференса для одной ячейки модели `catboost_20s` составило **5.58 мс** (на CPU Intel Core i5-13420H), что с запасом укладывается в требования реального времени (<10 мс).
- **Сложность горизонта 1с:** Предсказание смерти ровно за 1 секунду оказалось наиболее сложным (более низкие ROC-AUC / PR-AUC) из-за внезапного и непредсказуемого характера ганков и взрывного урона, в то время как более длинные горизонты (15–20с) показали высокую стабильность предсказаний.
